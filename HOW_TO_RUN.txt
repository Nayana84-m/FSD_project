SMARTSHIFT LOCAL RUN GUIDE
=========================

Requirements
------------
- Node.js 18 or later
- npm
- MongoDB Atlas account for cloud database mode (optional for local demo mode)

Install and configure
---------------------
1. Open PowerShell in the SmartShift project folder.
2. Install the project packages:
       npm install
3. If the project does not already have a .env file, create one:
       Copy-Item .env.example .env
4. Add your Atlas connection string to MONGODB_URI in .env.
   Keep MONGODB_DB_NAME=smartshift. Never share or commit .env.
5. In Atlas Network Access, allow your current public IP for local development.

Start the website and API
-------------------------
       npm start

Open the local URL printed in PowerShell, usually:
       http://localhost:3000

If port 3000 is already in use, use another PowerShell window or stop the
process using that port. Alternatively, start SmartShift on port 3001:
       $env:PORT = "3001"
       npm start
Then open:
       http://localhost:3001

Connection confirmation
-----------------------
Atlas mode prints:
       DATABASE_MODE=atlas database=smartshift

If MONGODB_URI is unset, the app starts in local JSON demo mode instead.

First-use account flow
----------------------
1. Select Manager and create an account with the cafe/business name.
2. Open the manager Profile and share its staff invite code with the team.
3. Add staff in the manager dashboard using their email and job details.
4. Staff select Staff > Create account and enter the matching email and invite
   code. This links the account to the manager's cafe and staff record.
5. Create shifts, assign suitable staff, and publish the roster. Staff can view
   their confirmed shifts and submit leave requests.

View saved Atlas data
---------------------
Atlas > SmartShiftCluster > Browse Collections > smartshift > application_state.
The cafe-specific records are stored in the document's workspaces array.

Deployment
----------
Deploy after confirming the local Atlas-backed flows. Keep MONGODB_URI in the
hosting provider's private environment settings; never put it in browser code
or commit it to Git.
